# Phase 3: isolated coordinator and persistence contract

Updated 18 October 2026. Implemented and tested locally with synthetic CPU
workers. No real model, GPU sweep, allocator intervention or deliberate OOM was
run. Real execution remains blocked by the incomplete preregistration receipt
and unresolved runtime mismatch.

## Components and ownership

- `gate.py`: CPU-only pushed-receipt, frozen-input/code and launch verification.
- `worker.py`: fresh interpreter entry, rechecks receipt and durable launch before
  invoking the Phase 2 engine. An exclusive fsynced claim rejects duplicate
  worker invocations for the same probe, including deliberate attempts.
- `processes.py`: child-only allocator environment, bounded streaming stdout/
  stderr, timeout/signal classification and process-group cleanup.
- `sweep.py`: three repeats, required/candidate grid, analytical admission,
  safe-budget bisection, identity/idle checks, resume and boundary summaries.
- `coordinator_store.py`: A3 reference adapter for run locks, durable mirrors,
  recovery artifacts and the shared deliberate-attempt ledger.

Person 2's `journal.py` remains intact. B2 owns review of persistence/schema
integration, including replacement of this adapter if needed. B4 still owns
chunked/static diagnostics and actual run operations. GPU acceptance requires
those integration checks; CPU tests do not sign off another person's work.

## Authorization and formal input contract

`kvcache check-receipt --receipt prereg/<actual-receipt>.json` performs CPU/Git
checks and never starts a GPU worker. Templates/drafts fail before remote lookup.
The verifier requires:

1. A complete receipt, distinct Person 1/Person 2 review roles with real timestamps,
   a shared experiment UUID and an absolute persistent state root outside source.
2. A clean source tree and a live GitHub remote branch head equal to local HEAD.
   Network failure, dirty/untracked source or an unpushed receipt fails closed.
3. A prediction Git ancestor and a separate later receipt commit. The formal
   prediction bytes must still match their original Git blob and recorded hash.
4. Scientific input hashes for config, provenance, experiment and derivation;
   execution hashes for `probe.py`, `telemetry.py`, `worker.py`, `gate.py`,
   `sweep.py`, `coordinator_store.py`, `processes.py`, `model_math.py`,
   `environment.py`, `cli.py` and `preregistration.py`. These files must match
   both the frozen prediction tree and current source.
5. A context inventory frozen in that prediction commit, with zero live tensors,
   only its own collector PID, and the implemented runtime. Newer Colab versions
   are rejected; this phase does not change the original stack proposal.
6. A separately named formal JSON outside `prereg/drafts`, status `PREREGISTERED`,
   `missing_evidence: []`, and the original scenario model with a real numerical
   commitment. The original draft is never edited into a receipt.

The formal JSON extends the analytical package with `execution_sha256`,
`context_inventory_path`, `context_inventory_sha256`, and `runtime` equal to
`probe.EXPECTED_RUNTIME`. Its `gpu_prediction` contains `usable_vram_bytes`,
`central_limit_tokens`, `limit_range_tokens` (conservative to optimistic, config
capped), and `central_budget_bytes_at_required_lengths` keyed by
`512`, `1024`, `2048`, `4096`, `8192`. The verifier recomputes these central values.
The verifier also requires the original parametric `scenarios` and recomputes
the numerical limit range. The analytical package's derivation and uncertainty remain
part of the reviewed commitment. The receipt adds `prediction_sha256`,
`experiment_id`, `persistent_state_root` and `remote_branch` to the template.
No real reviews, timestamps or receipts have been generated by this phase.

Remote URLs and reviewer metadata are human-supplied evidence. Git ancestry and
live remote comparison improve auditability; they cannot authenticate that a
human review happened or provide unforgeable publication timestamps.

A receipt alone cannot start a model. The worker must also find a matching
mirrored run manifest and unfinished durable `probe_started` event, claim that
probe once, and verify the global token for deliberate intent. There is no
`--authorized` or test-worker CLI switch.

## Scheduling and measurements

The parent checks Python/package metadata without importing torch and rejects
stack drift before launching or consuming a token. It reads idle state through NVML and refuses occupied
or unattributable GPU process state. Each point/repeat gets a fresh OS process
with allocator variables set before interpreter startup. Worker context free
memory must stay within 64 MiB of the frozen inventory; CUDA total, GPU UUID,
driver and pinned runtime must agree. Worker exit must restore idle driver usage
within 64 MiB before another point starts. Drift stops the run.

Admission uses the original conservative scenario against 90% of the frozen
context-adjusted free bytes, before weights. This is a scheduling estimate,
not a guaranteed upper bound or a revised preregistered prediction. Required
lengths and then candidate lengths increase in order; inadmissible points are
explicit skips. Every admitted length has three repeats. The original 256-token
bisection searches the safe-budget crossing, launching only admitted midpoints.
Actual reservation plus conservative fixed headroom must also fit the safe
budget to advance the lower endpoint.

Results distinguish largest observed success, lower/upper safe-budget endpoints
and an observed OOM upper point. No OOM point is invented from a safety skip or
timeout. Config caps may censor the boundary. Higher grid points after a stop
remain unattempted, not successes. The coordinator never silently calibrates or
replaces the advance analytical commitment with measured coefficients.

## Persistence, crash recovery and one-attempt semantics

Run/probe IDs are UUIDs. Point keys hash policy, scientific/environment
fingerprints, length, allocator, repeat and attempt intent. Successful keys are
skipped on resume. Failed/interrupted/deviating runs require review and a new
explicit run; there is no automatic retry or overwrite. A completed run resumes
from its saved summary. Changed manifest/code/environment fingerprints fail.

Local run files mirror to `<persistent_state_root>/runs/<run_id>`. Each artifact
is immutable; journal lines flush/fsync and mirror before advancing. Atomic
replacement includes directory fsync. Local loss restores from the durable
mirror. A torn last suffix is preserved as a recovery artifact before truncation;
interior corruption or divergent histories stop recovery. Orphaned starts become
`probe_interrupted` and are never launched automatically. A result lacking its
idle-return check also requires review.

One project-wide lock serializes experiment/run IDs and allocator variants on the supported
POSIX filesystem. The attempt ledger is outside run folders at
`<persistent_state_root>/global_deliberate_attempt.json`. The token is fsynced
**before** the start event and process launch. A crash can forfeit the attempt;
that is preferable to launching it twice. Success still consumes it. Deliberate
OOM records an upper point; accidental OOM blocks further model probes. No
session restart, allocator change, new experiment UUID or new run ID resets the ledger.
Keep the same persistent state root across all sessions/protocol revisions; moving
or deleting global state cannot preserve the one-attempt guarantee.

The optional `--deliberate-length L` fixes that intent in the run manifest. It
must exceed the largest successful default point and stay within the model
config domain. It is attempted once, after safe runs for both allocators. A
successful attempt is reported as success, without claiming the threshold was
confirmed. Changing intent on resume is rejected.

This reference adapter relies on POSIX locks, atomic rename and meaningful fsync
on a **single host or genuinely shared locking filesystem**. It does not establish
distributed locking across independent Colab hosts or prove cloud durability.
Use one coordinator at a time. B2 must validate the actual persistent mount and
session-loss behavior before real bulk execution; do not substitute `/tmp` or
an ephemeral `/content` directory for the declared persistent root.

## Logs, failures and reproduction

Retained stdout/stderr are bounded to 1 MiB each while streams continue draining;
metadata records total bytes, truncation and both full-stream and retained hashes.
Raw JSON is bounded to 16 MiB; oversized data preserves a prefix and is invalid.
Timeout, signal, missing/malformed output, authorization failure, backend failure
and typed CUDA OOM remain distinct. Partial output is preserved before rejection.
Normal failure records use null metrics when unavailable. Results are checked for
ID, request, execution policy, runtime/code hashes, snapshot invariants, cache
formula, weights and exit-status consistency. Workers cannot publish success by
printing a bare status string.
